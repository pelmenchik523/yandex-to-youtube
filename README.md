# YouTube → Яндекс Станция Lite 2

Мост на этом компьютере ищет трек на YouTube, скачивает MP3, отдаёт его по локальной сети на колонку и управляет воспроизведением через SSH. Сверху — веб-пульт и webhook для приватного навыка Алисы.

## Быстрый старт

```bash
cd ~/ytstation
./start.sh
```

Скрипт поднимает мост и SSH-туннель (если они ещё не запущены) и печатает адреса. Веб-пульт доступен по адресу:

```
localhost:8888
```

Остановить всё:

```bash
./stop.sh
```

## Полезные файлы

| Файл | Что внутри |
|---|---|
| `bridge.py` | мост, HTTP-сервер, API, webhook Алисы |
| `web/index.html` | веб-пульт (один файл, без внешних зависимостей) |
| `settings.json` | настройки YouTube (создаётся из веб-пульта) |
| `playlists.json` | сохранённые плейлисты (создаётся из веб-пульта) |
| `cookies.txt` | необязательный cookies-файл в формате Netscape |
| `pinproxy.py` | локальный обход IP-блокировки YouTube (см. ниже) |
| `bridge.log` | лог моста |
| `localhostrun.log` | лог туннеля и актуальный публичный URL |
| `start.sh` / `stop.sh` | запуск/остановка |
| `install.sh` | скрипт автоматической установки |

## Веб-пульт

- **Что играет** — обложка, название, прогресс, пауза/продолжить, следующий, предыдущий, стоп, громкость.
- **Поиск** — введите название, исполнителя или ссылку на плейлист и нажмите «Включить».
- **Очередь** — топ-5 результатов поиска; клик по строке включает трек.
- **YouTube** — вход в аккаунт одной кнопкой: открывается браузер, сессия автоматически сохраняется в мосте. Приватные плейлисты, плейлист по ссылке/ID, быстрые кнопки «Мне понравилось» (`LL`) и «Смотреть позже» (`WL`), сохранённые плейлисты. Прокси, JS-рантайм и лимит — в блоке «Дополнительно».
- **Подсветка** — цвет верхнего кольца, яркость, готовые цвета, режимы «Статика», «Дыхание», «Авто (Алиса)», «Выкл».
- **Питание** — усилитель (мгновенный mute/unmute), перезагрузка и полное выключение колонки.

Веб-пульт доступен только в локальной сети. Публичный туннель отдаёт наружу только `/alice` и `/health`; страница и API через него не доступны.

## Вход в YouTube и плейлисты

Мост не хранит пароль YouTube. Вход выполняется в браузере на этом компьютере, а мост забирает готовую сессию:

1. В карточке **YouTube** нажмите **«Войти»**.
2. В открывшемся окне Firefox войдите в нужный аккаунт Google/YouTube.
3. Вернитесь в веб-пульт и нажмите **«Я вошёл»**. Мост сохранит сессию в локальный `cookies.txt` (права 600) и проверит доступ к приватному плейлисту.
4. Если браузер не открылся автоматически, под кнопкой появится ссылка на YouTube — откройте её вручную на этом компьютере.

`cookies.txt` создаётся автоматически; экспортировать cookies вручную не нужно. **«Выйти»** удаляет сохранённую сессию из моста (аккаунт в браузере не затрагивается). **«Проверить»** повторяет проверку. Кнопка **«Войти»** остаётся доступной и при подключённом аккаунте: так можно обновить сессию или войти в другой аккаунт.

Если YouTube не открывается с этого компьютера напрямую (TLS-таймауты, блокировка провайдера), укажите **«Прокси для YouTube»** в блоке **«Дополнительно»** — например, `socks5://127.0.0.1:1080` или `http://127.0.0.1:8080`. Этот прокси используется только для `yt-dlp`.

После успешного входа:

- **«Мне понравилось (LL)»** — плейлист лайков;
- **«Смотреть позже (WL)»** — отложенные видео;
- вставьте ссылку вида `https://www.youtube.com/playlist?list=...` (или сырой ID) и нажмите **«Играть»;
- **«Сохранить»** добавляет текущий или указанный плейлист в список на этом компьютере (`playlists.json`).

Голосом: «включи любимые», «включи смотреть позже», «включи плейлист <название из сохранённых>».

Если проверка входа не проходит, войдите в YouTube в Firefox, нажмите **«Войти»** и затем **«Я вошёл»**. Для приватных плейлистов сессия обязательна. `settings.json`, `playlists.json` и `cookies.txt` — локальные файлы, их не нужно коммитить.

## Если провайдер блокирует YouTube

На этой сети `www.youtube.com` и `youtube.com` не открываются напрямую (TLS-таймаут), хотя `music.youtube.com` и обычный Google работают. Это IP-блокировка: тот же Google-фронтенд по другому адресу отдаёт YouTube нормально.

`start.sh` поднимает `pinproxy.py` на `127.0.0.1:8899`. Это маленький CONNECT-прокси: он выбирает рабочий Google-адрес для `www.youtube.com`, `youtube.com`, `m.youtube.com` и `youtu.be`, а TLS остаётся сквозным между `yt-dlp` и YouTube. Прокси слушает только localhost и не является общим анонимайзером.

В локальном `settings.json` на этом компьютере прописан `"proxy": "http://127.0.0.1:8899"`, поэтому веб-пульт уже использует его. Если вы включаете VPN или свой прокси — впишите его в поле **«Прокси для YouTube»** в блоке **«Дополнительно»** (или очистите поле), а `pinproxy` можно остановить. Если IP-блокировка изменится, прокси попробует другой адрес из `music.youtube.com`; при необходимости используйте VPN.

## «Всегда YouTube»

Основной путь:

1. **Перехват голоса (план Б)** — обычные команды без навыка: «Алиса, включи <трек>» на колонке играет с YouTube. Включается переключателем «Перехват голоса» в веб-пульте (или `native_watch` в `settings.json`, по умолчанию включён).

Резервный путь (legacy):

2. **Навык** — «Алиса, запусти навык Ютуб»: навык открывается и сразу включает основной плейлист (★ в веб-пульте; если не выбран — первый сохранённый). Пока навык открыт, все команды идут в него: «включи любимые», «включи смотреть позже», «включи <трек>», «дальше», «назад», «пауза», «громче». «Закрыть навык» завершает диалог, но звук продолжает играть отдельным процессом `gst-launch` на колонке.

## Перехват голоса (план Б)

Колонка — тонкий клиент: Алиса в облаке присылает ей директиву `AUDIO_PLAY` с подписанной ссылкой на Яндекс Музыку. Мост читает лог `maind.log` на колонке, берёт оттуда `streamId` (id трека Яндекс Музыки), получает название и исполнителя через Music API (запрос идёт через SSH-туннель колонки, потому что у компьютера VPN не из РФ), ищет трек на YouTube и играет его тем же `gst-launch`, что и остальной мост.

Что происходит по голосовой команде:

1. Нативная музыка начинает играть, мост глушит усилитель примерно через 0,05 с и командой `o` в `maind --cli` останавливает плеер Алисы.
2. Если до этого ничего не играло, пока скачивается первый раз — 2–6 секунд тишины (второй раз тот же трек играет сразу из кеша). Если играл прошлый трек, он продолжает звучать, пока готовится новый файл, и затем мост переключается без длинной паузы.
3. Трек звучит с YouTube. «Пауза», «громче», «тише» работают как обычно.
4. «Следующий трек» тоже перехватывается. Предзагрузки для него обычно нет, поэтому новый трек готовят 4–20 секунд; старый трек в это время играет.
5. Если скачивание сорвалось (например, YouTube отдал временную ошибку 405), мост повторяет попытку и пробует следующие результаты поиска.

«Продолжи» после паузы: облако иногда присылает не директиву продолжения, а новый `AUDIO_PLAY` того же трека. Мост ловит это, замораживает нативный аудио-демон (`SIGSTOP` для `maind --mediad`) и останавливает сессию Алисы, а наш трек в это время продолжает играть без двухсекундной тишины. Нативный фрагмент до заморозки — около 0,05 с (буфер ALSA).

Ограничения:

- Плейлисты и радио, запрошенные голосом без навыка, играют только первый трек: облачная очередь останавливается. Полноценные плейлисты — через навык или веб-пульт.
- Автопереход к следующему треку для голосовых запросов выключен (`native_auto_next: true` в `settings.json` включает, но с паузой).
- Если трек не удалось определить в Music API (например, аудиокнига), нативная музыка не глушится и играет как раньше.
- Если трек вообще не нашелся на YouTube, играет тишина (кроме случая аудиокниги/подкаста выше).
- Требуется SSH-доступ к колонке и токен в `/data/quasar/account_storage.dat` (он там уже есть у штатного аккаунта).

## Публичный адрес: Tailscale Funnel

Постоянный адрес даёт **Tailscale Funnel**:

```
https://ytstation-523.taila6048e.ts.net/alice
```

Он не меняется между перезапусками моста и компьютера. Домен привязан к узлу `ytstation-523` в тейлнете; сертификат выпускается автоматически.

Как это устроено:

- `tailscaled` работает в пользовательском режиме (без root):
  `~/.local/opt/tailscale_1.104.2_amd64/tailscaled --tun=userspace-networking`.
- Состояние и сокет: `~/.local/state/tailscale/`.
- `start.sh` поднимает `tailscaled`, вызывает `tailscale funnel --bg 8889` и печатает актуальный webhook.
- `stop.sh` выключает Funnel (`tailscale funnel --https=443 off`).
- Адрес для веб-пульта берётся из `settings.json` → `"public_url"`.
- Особенность сети: с этого компьютера адрес `*.ts.net` не открывается (провайдер закрывает исходящие соединения на IP-адреса входных узлов Tailscale), поэтому локальный `curl` на него даёт TLS-ошибку. Для серверов Яндекса адрес доступен — навык работает.

Резервный туннель `localhost.run` остаётся в `start.sh`, но его домен меняется при каждом переподключении, поэтому в навыке его использовать не нужно. Бесплатный `cloudflared` на этой сети не работает: наружу закрыт порт 7844.

## Питание и подсветка: детали

- **Усилитель** — это коммутация каналов FS2105 (`amixer cset numid=3/4`). Мгновенно выключает/включает звук, не трогая питание платы.
- **Перезагрузить** — `/sbin/reboot`.
- **Выключить** — `/sbin/poweroff`. Включить обратно удалённо нельзя: у Lite 2 нет Wake-on-LAN. Нужна кнопка на корпусе или умная розетка.
- **Подсветка** — sysfs `/sys/class/leds/plum:{red,green,blue}:ring{1,2,3}`. «Авто» возвращает кольцо Алисе (trigger `led_ring_fb`). «Статика» и «Дыхание» забирают кольцо у Алисы до нажатия «Авто».
- После перезагрузки колонки подсветка возвращается в авторежим.

## Если что-то не работает

```bash
cd ~/ytstation
tail -50 bridge.log
tail -20 localhostrun.log
./stop.sh && ./start.sh
```

Проверка колонки:

```bash
ssh -p 2222 root@192.168.1.206
```

Если нативная Яндекс.Музыка на колонке молчит, а через веб-пульт звук есть, проверьте на колонке:

```bash
grep -i proxy /system/vendor/quasar/launch.json
cat /proc/sys/net/ipv6/conf/wlan0/disable_ipv6
```

В `launch.json` не должно быть мёртвого `http_proxy`/`https_proxy` (например, `127.0.0.1:10808`, если на этом порту никто не слушает). Если у Wi-Fi нет рабочего глобального IPv6, оставьте `disable_ipv6=1`: иначе `souphttpsrc` может выбрать IPv6-адрес стрим-хоста и не скачать поток. Наш фикс — `/etc/sysctl.d/99-ytstation-ipv4.conf`.

Проверка моста:

```bash
curl http://127.0.0.1:8888/api/status
curl http://127.0.0.1:8889/health
```

Автозапуск после включения компьютера (по желанию):

```bash
crontab -e
# добавить строку:
@reboot /home/pelmenchik523/ytstation/start.sh >/dev/null 2>&1
```

## Установка

### Что понадобится

- Linux-компьютер, который будет работать мостом (проверено на Ubuntu/Debian).
- Python **3.10+**.
- `yt-dlp`, установленный через `pipx` или `pip` — не одиночным бинарником. Мосту нужен Python из окружения yt-dlp, чтобы экспортировать cookies из Firefox.
- Node.js — yt-dlp использует его для обхода JS-проверок YouTube.
- Firefox — в нём выполняется вход в YouTube.
- SSH-клиент и настроенный вход без пароля на Яндекс Станцию.
- По желанию — Tailscale для постоянного публичного webhook. Без него останется резервный `localhost.run` с меняющимся адресом.

### 1. Скопировать проект

```bash
git clone <адрес-репозитория> ~/ytstation
cd ~/ytstation
```

Если репозитория под рукой нет, просто скопируйте каталог с файлами в `~/ytstation`.
Каталог можно назвать иначе — скрипты используют свой фактический путь.

### 2. Установить зависимости

Ubuntu/Debian:

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv nodejs firefox ffmpeg openssh-client curl
python3 -m pip install --user --upgrade pipx
~/.local/bin/pipx install yt-dlp
```

Если `pipx` уже установлен, достаточно `pipx install yt-dlp`.
Проверьте, что команды доступны:

```bash
yt-dlp --version
node --version
firefox --version
```

Если `yt-dlp` не находится, добавьте `~/.local/bin` в `PATH`:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile
. ~/.profile
```

### 3. Настроить SSH к Станции

Станция должна быть в той же локальной сети. IP обычно виден в роутере; в примерах используется `192.168.1.206`.

```bash
ssh-keygen -t ed25519 -N ''        # если ключа ещё нет
ssh-copy-id -p 2222 root@192.168.1.206
ssh -p 2222 root@192.168.1.206 'echo ok'
```

Последняя команда должна вывести `ok` без запроса пароля.
Если IP другой, `install.sh` запишет его в `station.env`, а `start.sh` подхватит при запуске. Можно также задать вручную:

```bash
STATION_HOST=192.168.1.50 ./start.sh
```

или изменить значение по умолчанию в `bridge.py` (константа `STATION_HOST`).

### 4. Запустить установщик

```bash
chmod +x install.sh start.sh stop.sh
./install.sh
```

Скрипт:

- проверит Python, yt-dlp, Node.js и Firefox;
- спросит IP Станции и проверит SSH;
- создаст `cache/`, `settings.json`, `playlists.json` и `station.env`;
- предложит добавить автозапуск в `crontab`.

### 5. Запустить мост

```bash
./start.sh
```

Скрипт поднимет `pinproxy` (обход блокировки YouTube), мост, резервный туннель и, если установлен, Tailscale Funnel. В конце он печатает адреса:

```
web ui:  http://192.168.1.167:8888/
webhook: https://ytstation-523.taila6048e.ts.net/alice
```

Откройте веб-пульт в браузере:

```
http://<IP-компьютера>:8888/
```

### 6. Войти в YouTube

1. В карточке **YouTube** нажмите **«Войти»** — откроется Firefox.
2. Войдите в нужный аккаунт Google/YouTube.
3. Вернитесь в веб-пульт и нажмите **«Я вошёл»**.
4. Мост сохранит сессию в `cookies.txt` с правами `600` и проверит доступ к плейлисту «Мне понравилось».

Кнопка **«Проверить»** повторяет проверку, **«Выйти»** удаляет сессию из моста (аккаунт в браузере не затрагивается). Пароль вводится только на сайте Google и мосту не передаётся.

### 7. Публичный webhook для навыка Алисы

Постоянный адрес в этой установке:

```
https://ytstation-523.taila6048e.ts.net/alice
```

Его даёт Tailscale Funnel. Узел `ytstation-523` зарегистрирован в вашем тейлнете, поэтому адрес не меняется между перезапусками. Сертификат выпускается автоматически.

Если Tailscale ещё не установлен:

1. Установите Tailscale удобным способом (пакет или официальный статический бинарник).
2. Выполните `tailscale up` и войдите в свой аккаунт Tailscale.
3. Запустите `./start.sh` — он включит Funnel на порт `8889`.

В этой установке бинарники лежат в `~/.local/opt/tailscale_1.104.2_amd64`, состояние — в `~/.local/state/tailscale`. Если каталог другой, задайте `TS_DIR` перед запуском:

```bash
TS_DIR=/путь/к/tailscale ./start.sh
```

Затем в [конструкторе навыков](https://dialogs.yandex.ru/developer) укажите webhook:

```
https://<ваш-узел>.<ваш-тейлнет>.ts.net/alice
```

Без Tailscale `start.sh` поднимет резервный туннель `localhost.run`. Его адрес меняется после переподключения, поэтому для постоянного навыка он неудобен.

### 8. Автозапуск (по желанию)


Остановить всё:

```bash

```


В ответе `/api/youtube/status` должно быть `"logged_in": true` и сообщение о доступности плейлиста «Мне понравилось».

### Обновление

```bash
cd ~/ytstation
./stop.sh
git pull
pipx upgrade yt-dlp
./start.sh
```

`settings.json`, `playlists.json`, `cookies.txt` и `station.env` — локальные файлы, они не хранятся в git и не перезаписываются при обновлении.

## Заключение

Мост ищет треки на YouTube, играет их на Яндекс Станции и управляется из веб-пульта или голосом. Основной режим — перехват обычных голосовых команд Алисы (план Б); приватный навык остаётся как резервный путь. Постоянный webhook через Tailscale Funnel делает интеграцию с Алисой независимой от перезапусков компьютера.
