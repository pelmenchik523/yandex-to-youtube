# YouTube → Яндекс Станция Lite 2

Мост на этом компьютере ищет трек на YouTube, скачивает аудио, отдаёт его по
локальной сети на колонку и управляет воспроизведением через SSH. Сверху —
веб-пульт и перехват обычных голосовых команд Алисы (план Б).

## Быстрый старт

```bash
cd ~/ytstation
./start.sh
```

Скрипт поднимает локальный прокси и мост (если они ещё не запущены) и печатает
адрес веб-пульта:

```
http://<IP-компьютера>:8888/
```

Остановить всё:

```bash
./stop.sh
```

## Полезные файлы

| Файл | Что внутри |
|---|---|
| `bridge.py` | мост, HTTP-сервер, API, перехват голоса |
| `web/index.html` | веб-пульт (один файл, без внешних зависимостей) |
| `settings.json` | настройки YouTube (создаётся из веб-пульта) |
| `playlists.json` | сохранённые плейлисты (создаётся из веб-пульта) |
| `cookies.txt` | cookies-файл YouTube в формате Netscape |
| `pinproxy.py` | локальный обход IP-блокировки YouTube (см. ниже) |
| `setup-station-dns.sh` | блокировка нативных аудиопотоков Яндекс Музыки на Станции |
| `station.env` | IP/порт/пользователь Станции (создаётся `install.sh`) |
| `bridge.log` | лог моста |
| `start.sh` / `stop.sh` | запуск/остановка |
| `install.sh` | скрипт автоматической установки |

## Веб-пульт

- **Что играет** — обложка, название, прогресс, пауза/продолжить, следующий, предыдущий, стоп, громкость.
- **Поиск** — введите название, исполнителя или ссылку на плейлист и нажмите «Включить».
- **Очередь** — топ-5 результатов поиска; клик по строке включает трек.
- **YouTube** — вход в аккаунт одной кнопкой: открывается браузер, сессия автоматически сохраняется в мосте. Приватные плейлисты, плейлист по ссылке/ID, быстрые кнопки «Мне нравится» (`LM`, YouTube Music), «Тренды YouTube Music», «Лайки YouTube» (`LL`) и «Смотреть позже» (`WL`), сохранённые плейлисты. Прокси, JS-рантайм и лимит — в блоке «Дополнительно».
- **Подсветка** — цвет верхнего кольца, яркость, готовые цвета, режимы «Статика», «Дыхание», «Авто (Алиса)», «Выкл».
- **Питание** — усилитель (мгновенный mute/unmute), перезагрузка и полное выключение колонки.

Веб-пульт доступен только в локальной сети. Наружу ничего не публикуется.

## Вход в YouTube и плейлисты

Мост не хранит пароль YouTube. Вход выполняется в браузере на этом компьютере, а мост забирает готовую сессию:

1. В карточке **YouTube** нажмите **«Войти»**.
2. В открывшемся окне Firefox войдите в нужный аккаунт Google/YouTube.
3. Вернитесь в веб-пульт и нажмите **«Я вошёл»**. Мост сохранит сессию в локальный `cookies.txt` (права 600) и проверит доступ к приватному плейлисту.
4. Если браузер не открылся автоматически, под кнопкой появится ссылка на YouTube — откройте её вручную на этом компьютере.

`cookies.txt` создаётся автоматически; экспортировать cookies вручную не нужно. **«Выйти»** удаляет сохранённую сессию из моста (аккаунт в браузере не затрагивается). **«Проверить»** повторяет проверку. Кнопка **«Войти»** остаётся доступной и при подключённом аккаунте: так можно обновить сессию или войти в другой аккаунт.

Если YouTube не открывается с этого компьютера напрямую (TLS-таймауты, блокировка провайдера), укажите **«Прокси для YouTube»** в блоке **«Дополнительно»** — например, `socks5://127.0.0.1:1080` или `http://127.0.0.1:8080`. Этот прокси используется только для `yt-dlp`.

После успешного входа:

- **«Мне нравится (YouTube Music)»** — плейлист лайков именно из YouTube Music (`LM`), а не из обычного YouTube;
- **«Тренды YouTube Music»** — глобальный чарт YouTube Music (не Яндекс Музыка);
- **«Лайки YouTube (LL)»** — старый плейлист лайков обычного YouTube;
- **«Смотреть позже (WL)»** — отложенные видео;
- вставьте ссылку вида `https://www.youtube.com/playlist?list=...` (или сырой ID) и нажмите **«Играть»**;
- **«Сохранить»** добавляет текущий или указанный плейлист в список на этом компьютере (`playlists.json`).

Если проверка входа не проходит, войдите в YouTube в Firefox, нажмите **«Войти»** и затем **«Я вошёл»**. Для приватных плейлистов сессия обязательна. `settings.json`, `playlists.json` и `cookies.txt` — локальные файлы, их не нужно коммитить.

## Если провайдер блокирует YouTube

На этой сети `www.youtube.com` и `youtube.com` не открываются напрямую (TLS-таймаут), хотя `music.youtube.com` и обычный Google работают. Это IP-блокировка: тот же Google-фронтенд по другому адресу отдаёт YouTube нормально.

`start.sh` поднимает `pinproxy.py` на `127.0.0.1:8899`. Это маленький CONNECT-прокси: он выбирает рабочий Google-адрес для `www.youtube.com`, `youtube.com`, `m.youtube.com`, `music.youtube.com` и `youtu.be`, а TLS остаётся сквозным между `yt-dlp` и YouTube. Прокси слушает только localhost и не является общим анонимайзером.

В локальном `settings.json` на этом компьютере прописан `"proxy": "http://127.0.0.1:8899"`, поэтому веб-пульт уже использует его. Если вы включаете VPN или свой прокси — впишите его в поле **«Прокси для YouTube»** в блоке **«Дополнительно»** (или очистите поле), а `pinproxy` можно остановить. Если IP-блокировка изменится, прокси попробует другой адрес из `music.youtube.com`; при необходимости используйте VPN.

## Перехват голоса (план Б)

Колонка — тонкий клиент: Алиса в облаке присылает ей директиву `AUDIO_PLAY` с подписанной ссылкой на Яндекс Музыку. Мост читает лог `maind.log` на колонке, ловит распознанную фразу и ищет этот трек на YouTube. `streamId` используется только как маркер запроса: **к API Яндекс Музыки мост не обращается** — ни за метаданными, ни за токеном, ни через SOCKS. Готовый трек играет тем же `gst-launch`, что и остальной мост.

Чтобы Яндекс Музыка не успевала звучать, на Станции настроен локальный DNS-блок: `*.strm.yandex.net` отвечает `127.0.0.1`. Алиса по-прежнему распознаёт команду и присылает `AUDIO_PLAY`, TTS работает, но нативный аудиопоток Яндекс Музыки скачать не может. Дополнительно мост при `player_start` сразу замораживает `maind --mediad` (`SIGSTOP`) и отправляет `o` в `maind --cli`; усилитель глушится только если заморозка не удалась. Настройка ставится `setup-station-dns.sh` (её запускает `install.sh`) и сохраняется в `/data/unbound/unbound.conf`.

Что происходит по голосовой команде:

1. Нативная Яндекс Музыка не звучит: её поток заблокирован на DNS, а плеер Алисы мост останавливает командой `o` в `maind --cli`. TTS-ответ Алисы при этом слышен.
2. Если до этого ничего не играло, пока скачивается первый раз — 2–6 секунд тишины (второй раз тот же трек играет сразу из кеша). Если играл прошлый трек, он продолжает звучать, пока готовится новый файл, и затем мост переключается без длинной паузы.
3. Трек звучит с YouTube. «Пауза», «громче», «тише» работают как обычно.
4. «Дальше» / «следующий трек» не создаёт новый запрос в Яндекс Музыку. Мост берёт следующий трек из локальной очереди YouTube (сохранённый плейлист, результаты поиска или остальные результаты по последнему голосовому запросу), а облачную директиву с новым `streamId` просто глушит.
5. После конкретной песни, включённой голосом, мост в фоне строит **YouTube-микс по этой песне** (`RD`-плейлист) и ставит его в очередь. Когда песня заканчивается, микс продолжается автоматически.
6. «Включи музыку» без названия трека берёт **случайную песню из трендов/рекомендаций YouTube Music** и запускает **микс по этой песне** (`RD`-плейлист): сначала звучит сама песня, затем продолжается микс. Если микс недоступен, играет очередь из остальных трендовых треков; если недоступны и они — микс от последнего трека, затем поиск по музыке. Если YouTube сейчас недоступен, играет случайный трек из кеша и очередь из остальных кешированных треков.
7. «Включи тренды», «включи трендовые треки» или кнопка **«Тренды YouTube Music»** включают весь глобальный чарт YouTube Music. Это не персональный раздел «Трендовые треки для вас» из Яндекс Музыки: к API Яндекс Музыки мост не обращается.
8. Если скачивание сорвалось (например, YouTube отдал временную ошибку 405), мост повторяет попытку и пробует следующие результаты поиска.

«Продолжи» после паузы: облако иногда присылает не директиву продолжения, а новый `AUDIO_PLAY` того же трека. Мост ловит это, замораживает нативный аудио-демон (`SIGSTOP` для `maind --mediad`) и останавливает сессию Алисы, а наш трек в это время продолжает играть без двухсекундной тишины. Нативная Яндекс Музыка при этом не звучит: её поток уже заблокирован на DNS.

Перехват включается переключателем **«Перехват голоса»** в веб-пульте или параметром `native_watch` в `settings.json` (по умолчанию включён).

Ограничения:

- Плейлисты и радио, запрошенные голосом, играют только первый трек: облачная очередь останавливается. Дальше можно переключать локальную очередь кнопкой «Дальше» или голосом.
- Автопереход к следующему треку для голосовых запросов выключен (`native_auto_next: true` в `settings.json` включает локальную очередь, без запросов в Яндекс Музыку).
- Если распознанную фразу не удалось использовать (например, запрос из приложения без голоса, аудиокнига или слишком общая команда), мост не глушит нативную музыку — она играет как раньше.
- Если трек вообще не нашёлся на YouTube, играет тишина (кроме случая выше).
- Требуется только SSH-доступ к колонке. Токен Яндекс Музыки и SOCKS-туннель больше не нужны.

## Питание и подсветка: детали

- **Усилитель** — это коммутация каналов FS2105 (`amixer cset numid=3/4`). Мгновенно выключает/включает звук, не трогая питание платы.
- **Перезагрузить** — `/sbin/reboot`.
- **Выключить** — `/sbin/poweroff`. Включить обратно удалённо нельзя: у Lite 2 нет Wake-on-LAN. Нужна кнопка на корпусе или умная розетка.
- **Подсветка** — sysfs `/sys/class/leds/plum:{red,green,blue}:ring{1,2,3}`. «Авто» возвращает кольцо Алисе (trigger `led_ring_fb`). «Статика» и «Дыхание» забирают кольцо у Алисы до нажатия «Авто».
- После перезагрузки колонки подсветка возвращается в авторежим.

## Если что-то не работает

```bash
cd ~/ytstation
tail -50 bridge.log
./stop.sh && ./start.sh
```

Проверка колонки:

```bash
ssh -p 2222 root@192.168.1.206
```

Если нативная Яндекс.Музыка на колонке молчит, а через веб-пульт звук есть, проверьте на колонке:

```bash
grep -i proxy /system/vendor/quasar/launch.json
cat /proc/sys/net/ipv6/conf/wlan0/disable_ipv6
```

В `launch.json` не должно быть мёртвого `http_proxy`/`https_proxy` (например, `127.0.0.1:10808`, если на этом порту никто не слушает). Если у Wi-Fi нет рабочего глобального IPv6, оставьте `disable_ipv6=1`: иначе `souphttpsrc` может выбрать IPv6-адрес стрим-хоста и не скачать поток. Наш фикс — `/etc/sysctl.d/99-ytstation-ipv4.conf`.

Проверка моста:

```bash
curl http://127.0.0.1:8888/api/status
curl http://127.0.0.1:8888/health
curl 'http://127.0.0.1:8888/api/youtube/status?force=1'
```

```bash
crontab -e
# добавить строку:
@reboot /home/pelmenchik523/ytstation/start.sh >/dev/null 2>&1
```

## Установка

### Что понадобится

- Linux-компьютер, который будет работать мостом (проверено на Ubuntu/Debian).
- Python **3.10+**.
- `yt-dlp`, установленный через `pipx` или `pip` — не одиночным бинарником. Мосту нужен Python из окружения yt-dlp, чтобы экспортировать cookies из Firefox.
- Node.js — yt-dlp использует его для обхода JS-проверок YouTube.
- Firefox — в нём выполняется вход в YouTube.
- SSH-клиент и настроенный вход без пароля на Яндекс Станцию.

### 1. Скопировать проект

```bash
git clone <адрес-репозитория> ~/ytstation
cd ~/ytstation
```

Если репозитория под рукой нет, просто скопируйте каталог с файлами в `~/ytstation`.
Каталог можно назвать иначе — скрипты используют свой фактический путь.

### 2. Установить зависимости

Ubuntu/Debian:

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv nodejs firefox ffmpeg openssh-client curl
python3 -m pip install --user --upgrade pipx
~/.local/bin/pipx install yt-dlp
```

Если `pipx` уже установлен, достаточно `pipx install yt-dlp`.
Проверьте, что команды доступны:

```bash
yt-dlp --version
node --version
firefox --version
```

Если `yt-dlp` не находится, добавьте `~/.local/bin` в `PATH`:

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.profile
. ~/.profile
```

### 3. Настроить SSH к Станции

Станция должна быть в той же локальной сети. IP обычно виден в роутере; в примерах используется `192.168.1.206`.

```bash
ssh-keygen -t ed25519 -N ''        # если ключа ещё нет
ssh-copy-id -p 2222 root@192.168.1.206
ssh -p 2222 root@192.168.1.206 'echo ok'
```

Последняя команда должна вывести `ok` без запроса пароля.
Если IP другой, `install.sh` запишет его в `station.env`, а `start.sh` подхватит при запуске. Можно также задать вручную:

```bash
STATION_HOST=192.168.1.50 ./start.sh
```

или изменить значение по умолчанию в `bridge.py` (константа `STATION_HOST`).

### 4. Запустить установщик

```bash
chmod +x install.sh start.sh stop.sh setup-station-dns.sh
./install.sh
```

Скрипт:

- проверит Python, yt-dlp, Node.js и Firefox;
- спросит IP Станции, проверит SSH и запишет адрес в `station.env` и в `bridge.py`;
- включит DNS-блокировку нативных аудиопотоков Яндекс Музыки на Станции;
- создаст `cache/`, `settings.json` и `playlists.json`;
- предложит добавить автозапуск в `crontab`.

Если нужно включить или повторить DNS-блокировку отдельно:

```bash
./setup-station-dns.sh
```

### 5. Запустить мост

```bash
./start.sh
```

Скрипт поднимет `pinproxy` и мост. В конце он напечатает адрес веб-пульта:

```
web ui:  http://192.168.1.167:8888/
```

Откройте его в браузере:

```
http://<IP-компьютера>:8888/
```

### 6. Войти в YouTube

1. В карточке **YouTube** нажмите **«Войти»** — откроется Firefox.
2. Войдите в нужный аккаунт Google/YouTube.
3. Вернитесь в веб-пульт и нажмите **«Я вошёл»**.
4. Мост сохранит сессию в `cookies.txt` с правами `600` и проверит доступ к лайкам YouTube/YouTube Music.

Кнопка **«Проверить»** повторяет проверку, **«Выйти»** удаляет сессию из моста (аккаунт в браузере не затрагивается). Пароль вводится только на сайте Google и мосту не передаётся.

### 7. Автозапуск (по желанию)

```bash
crontab -e
```

Добавьте строку (замените путь и имя пользователя на свои):

```
@reboot /home/pelmenchik523/ytstation/start.sh >/dev/null 2>&1
```

Остановить всё:

```bash
cd ~/ytstation
./stop.sh
```

### Проверка после установки

```bash
cd ~/ytstation
curl -s http://127.0.0.1:8888/health
curl -s 'http://127.0.0.1:8888/api/youtube/status?force=1'
tail -30 bridge.log
```

Ожидаемый ответ `/health`:

```json
{"ok": true, "ytdlp": "...", "pc_ip": "...", "station": "..."}
```

В ответе `/api/youtube/status` должно быть `"logged_in": true` и сообщение о доступности лайков YouTube/YouTube Music.

### Обновление

```bash
cd ~/ytstation
./stop.sh
git pull
pipx upgrade yt-dlp
./start.sh
```

`settings.json`, `playlists.json`, `cookies.txt` и `station.env` — локальные файлы, они не хранятся в git и не перезаписываются при обновлении.

## Заключение

Мост ищет треки на YouTube, играет их на Яндекс Станции и управляется из веб-пульта или обычными голосовыми командами через перехват (план Б).
